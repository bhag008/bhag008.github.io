# デュエルマスターズ 第1弾〜第3弾再現アプリ — 開発メモ

## 概要
実在のTCG「デュエルマスターズ」のコアルールを再現した、ひとり用(CPU対戦)のブラウザゲーム。
`game_app/*` の他アプリ(灰の塔・アルカナバトル等)と同じ vanilla JS ES modules・ビルドレス構成。
ライブ: `https://bhag008.github.io/game_app/duel_masters_app/`

## カードプールについて
`js/cards.js` は2002年発売の第1弾(DM-01・120種)、第2弾(DM-02・60種、進化クリーチャー導入)、
第3弾(DM-03・60種、マナゾーン単色シナジー導入)の合計**240種**を、公式カードデータベース
(dm.takaratomy.co.jp)とファンWiki(dmwiki.net、各カード個別ページ)を調査エージェント経由で
参照し、カード名・文明・コスト・パワー・種族・ルールテキスト・進化条件をそのまま再現したもの。
デッキ構築画面では全弾のカードが文明ごとに混在して表示され、実際の紙のTCG同様どの弾のカードも
自由に組み合わせてデッキを作れる。
- イラストは著作権上の理由から実装していない(テキスト+文明カラーのカード表示)
- 各カードに `set: 'DM-02'` / `set: 'DM-03'` を付与(未指定はDM-01)。数枚は情報源で表記ゆれが
  あり個別に再調査済み
- カードリストの誤りが見つかった場合は `js/cards.js` の `CARD_DB` を直接修正すればよい(データ駆動)

## 進化クリーチャー(第2弾で追加)
- バトルゾーンのクリーチャーは `{uid, tapped, sickness, stack:[{uid,cardId}, ...]}` という「スタック」
  で表現する。`stack` の最後尾(一番上)が現在の姿で、`engine.cardOf(inst)` が常にそれを返す
- 進化クリーチャーは手札から通常のコストを払って、進化元(`evolution.fromRaces` に一致する種族を
  持つ、自分のバトルゾーンのクリーチャー)の上に重ねる(`playEvolutionCard`)。**召喚酔いを受けない**
  ため出したターンにそのまま攻撃できる(公式のルール通り)
- バトルゾーンを離れる(破壊/バウンス/マナ送り/山札送り)時は進化元ごと束になって移動し、
  移動先ではバラバラの個別カードに戻る。各カードの「かわりに手札/マナに置く」等の置換効果は
  カードごとに個別に判定される
- 進化元の判定は「現在の一番上のカードの種族」で行うため、進化の上にさらに進化を重ねることも可能

## マナゾーン単色シナジー(第3弾で追加)
- 「自分のマナゾーンにあるカードがすべて○○文明である間」条件は `isManaMonoColor(side, civ)` で
  判定(マナが1枚もない場合は成立しない)。パワー上昇(`staticPowerIfManaMonoColor`)、ブロッカー付与
  (`blockerIfManaMonoColor`)、W・ブレイカー付与(`doubleBreakerIfManaMonoColor`)の3種類に対応
- 同文明カウントスケーリング(`powerPerOtherSameCivInBattle`)はバトルゾーンの「自分以外」の
  同文明クリーチャー数に比例してパワーが増える常時能力(混沌魚・牙男・奇面ざくろ等)
- 他クリーチャーへのオーラ付与系(`auraBuffOthersOfCivWhileAttacking`=攻撃中のみ固定値バフ、
  `auraGrantBlockerToOthersOfCiv`=ブロッカー付与、`auraGrantUnblockableToOthersOfCiv`=ブロック不可付与)
  は自分を含まず「他の同文明クリーチャー」にのみ及ぶ
- 破壊時の身代わり(`redirectAllyDeathTo`: 'hand' | 'mana')は、対象クリーチャーがバトルゾーンに
  いる間、他の同文明の味方が墓地に置かれる代わりに手札/マナに移動する置換効果(大昆虫ギガマンティス・
  絶望の魔黒ジャックバイパー)
- 破壊時にシールド化(`onDestroy: 'shield'`)は墓地の代わりに裏向きシールドとしてシールドゾーンへ
  (雷雲の守護者ラーザ・ベガ・予言者アレス)
- 進化クリーチャーの一番上のカードだけを墓地に送る「剥がし」効果(`peelTopOfEvolution`、シェル・
  ポーチ)は、スタックの最上段のみ墓地送りにし、破壊トリガーは発生させない(進化元は残る)
- 攻撃制限系: `cannotAttackIfOutnumbered`(バトルゾーンの数で相手に負けていると攻撃不可、奇襲兵
  ブルレイザー)、`cannotAttackCreatures`(クリーチャーを攻撃対象にできない、夜明けの超人)
- 呪文が墓地でなくマナゾーンに置かれる(`castGoesToMana`)は第2弾から存在するパターンをS・トリガー
  呪文(ライト・ブーメラン)にも適用
- シールドを好きな枚数選んでマナ化する効果(逆転のオーロラ)は `kind: 'shieldQuantity'` という
  疑似対象種別を使い、「0〜現在のシールド枚数」を選択肢として提示する(人間側はモーダルで数値を選択、
  CPU側は`ai.js`で2枚を上限とする簡易ヒューリスティックを使用)
- 魔流毒(「自分の闇のクリーチャーを1体破壊しなければ唱えられない」)は、唱える条件を「自分の闇の
  クリーチャーが1体以上いること」を対象存在チェックで表現し、破壊自体を対象選択の一部として実装
  (対象がいない場合はS・トリガーとしても使用不可)

## アーキテクチャ
- `js/state.js` — `nextUid`、デッキ(`duelmasters.decks.v1`)と戦績(`duelmasters.meta.v1`)の localStorage 永続化
- `js/cards.js` — カードDB(240種)、文明定義、キーワード能力ヘルパー、効果ファクトリ関数群、デッキ検証
- `js/engine.js` — `DuelEngine` クラス。ターン進行、マナ支払い(コスト軽減オーラを考慮した
  `effectiveCost`)、進化(`playEvolutionCard`/`getEvolutionTargets`)、攻撃対象制限、ブロック可否判定
  (パワー条件付き/種族グローバル不可/マナ単色条件を含む)、攻撃時能力(`onAttack`、
  `pendingAttackTrigger`でブロック判定より先に解決。`_resolvingAttackerUid` で自己参照可能)、
  バトル解決(スレイヤー・バトル後自壊・ブロック後アンタップ等)、シールドブレイクとS・トリガーの
  キュー管理、CIP能力の「先に出してから対象を選ぶ」実タイミング再現、マナ単色シナジー(`isManaMonoColor`)
- `js/ai.js` — CPUの意思決定(マナチャージ・プレイ・進化・攻撃・攻撃時能力・ブロック・S・トリガー・
  `ownManaCard`/`shieldQuantity`を含む対象選択ヒューリスティック)
- `js/decks.js` — CPU用プリセットデッキ(各文明の全カード=DM-01+DM-02+DM-03をレアリティ別採用枚数で
  40枚以上に構築、モノカラー5種。進化とその進化元が自然と同じデッキに入るよう文明単位で構築)
- `js/main.js` — 画面遷移・DOM描画・対象選択モーダル・進化元選択・攻撃時能力の対象選択

## ルール実装上の設計判断・簡略化
- シールドは自分の分も含めて内容を伏せて表示。ブレイクされて初めて中身が分かる
- クリーチャーを攻撃対象にできるのは原則タップ状態のもののみ。アンタップキラー/一時許可/
  「タップされていなくても攻撃できる」チーム効果(クエイク・ゲート等)は例外
- パワーアタッカー系(固定値/条件付き/他の数につき増加/墓地枚数につき増加)は「攻撃中のみ」、
  種族オーラ(機神装甲ヴァルディオス等)は「常時」など、キーワードごとに適用タイミングを区別
- スレイヤーは「相手を戦闘結果に関わらず破壊」、バトル後自壊は「結果に関わらず自分も破壊」
- 「相手が自分のクリーチャーを選ぶ」効果(腐食虫スワンプワーム等)は簡略化のため、常に相手側の
  一番パワーが低いクリーチャーを自動選択する(効果自体は正確、選ぶ主体だけ簡略化)
- 手札を見ずに選ぶハンデスは完全ランダムで自動解決。相手のシールドを見る効果は状態を変えず、
  人間プレイヤー側が見た時だけログに内容を表示する(CPU側が見た内容は人間には見せない)
- 山札を見て1枚加える/マナに置く系は、実際の山札全体から検索するモーダルを実装
- ダイヤモンド・カッターの「攻撃制限を全て無視」は召喚酔い・攻撃不可・相手プレイヤー攻撃不可を
  まとめてターン中バイパスするフラグ(`turnFlags[side].ignoreAttackRestrictions`)として実装
- マナ支払いの文明チェックは「デュエルマスタープレイス」仕様: 必要な文明のカードがマナゾーンに
  1枚でも存在すれば(タップ済みでも可)コストは支払え、実際にタップする札は文明を問わず先頭から
  必要枚数を機械的にタップするだけでよい(紙のTCGの「タップする札の中に文明を含める」制約より緩い)
- 自分/相手のマナゾーンには文明ごとの内訳(未タップ/合計)を色付きタグで常時表示する
  (マナゾーンは公開領域のため、相手の内訳も見せて問題ない)
- 灼熱波・スネークアタックの「自分のシールドが1枚でもあれば裏向きのまま1枚選び墓地に置く」は
  コストではなく付随効果として簡略化し、`millOwnShieldRandom` でランダムな1枚を内容を見ずに墓地送り

## 未実装/今後の拡張候補
- クラウド同期、ローカル2人対戦は今回スコープ外
- CPU用プリセットは現状モノカラー5種のみ。多色デッキや難易度差のあるCPUの追加は容易(`js/decks.js`)。
  加えてCPU対戦相手選択画面では、プレイヤーが保存した(条件を満たす)デッキも「あなたが編成したデッキ」
  として選択でき、CPUがそのままそのデッキを使って対戦する(ミラーマッチや自作デッキの練習用)
- 「相手が自分のクリーチャーを選ぶ」効果を実際に相手側(人間プレイヤーの番)で選ばせるインタラクティブ化
- 第4弾以降を追加する場合も同じデータ駆動構造(`CARD_DB`への追加+必要なら新キーワード実装)で対応可能

## 動作確認手順
`.claude/launch.json` の `duel_masters` エントリ(ポート8129)でプレビュー可能。ブラウザでのUI操作に加え、
`cards.js`/`engine.js` をブラウザコンソールから直接importしてエンジン単体のシナリオテスト
(進化召喚→召喚酔い無視で即攻撃→W・ブレイカーでシールド2枚割り、進化スタックの破壊で進化元ごと
墓地へ、攻撃時能力の発動順、コスト軽減、種族オーラ、グローバル種族ブロック不可、スレイヤーの道連れ、
攻撃制限無視、ブロック後アンタップ、破壊時トリガー、手札を捨てて手札に戻る、マナ単色でのパワー/
ブロッカー/W・ブレイカー付与、同文明カウントによるパワー上昇、破壊の身代わり、破壊時シールド化、
進化の剥がし、攻撃時能力での自己バフ参照、シールドの好きな枚数マナ化、呪文のマナゾーン送り等)を
実施し、いずれも意図通り動作することを確認済み。
