# デュエルマスターズ 第1弾〜第6弾再現アプリ — 開発メモ

## 概要
実在のTCG「デュエルマスターズ」のコアルールを再現した、ひとり用(CPU対戦)のブラウザゲーム。
`game_app/*` の他アプリ(灰の塔・アルカナバトル等)と同じ vanilla JS ES modules・ビルドレス構成。
ライブ: `https://bhag008.github.io/game_app/duel_masters_app/`

## カードプールについて
`js/cards.js` は2002〜2003年発売の第1弾(DM-01・120種)、第2弾(DM-02・60種、進化クリーチャー導入)、
第3弾(DM-03・60種、マナゾーン単色シナジー導入)、第4弾(DM-04・60種、両陣営に及ぶ部族オーラ・
コスト税・S・トリガー/呪文ロック導入)、第5弾(DM-05・60種、サバイバー種族・T(トリプル)・ブレイカー・
スピードアタッカー導入)、第6弾(DM-06「闘魂編第1弾」・120種のうちDM-01再録3種を除く117種を新規収録、
タップ能力(TT)・マッドネス・山札破壊・シールド焼却導入)の合計**477種**を、公式カードデータベース
(dm.takaratomy.co.jp)とファンWiki(dmwiki.net、各カード個別ページ)を調査エージェント経由で参照し、
カード名・文明・コスト・パワー・種族・ルールテキスト・進化条件をそのまま再現したもの。デッキ構築画面
では全弾のカードが文明ごとに混在して表示され、実際の紙のTCG同様どの弾のカードも自由に組み合わせて
デッキを作れる。
- イラストは著作権上の理由から実装していない(テキスト+文明カラーのカード表示)
- 各カードに `set: 'DM-02'` / `'DM-03'` / `'DM-04'` / `'DM-05'` / `'DM-06'` を付与(未指定はDM-01)。
  数枚は情報源で表記ゆれがあり個別に再調査済み
- DM-06の収録カードのうちスパイラル・ゲート/デス・スモーク/ディメンジョン・ゲートの3種はDM-01の
  再録であり、既存のDM-01版カードと完全に同一効果のため重複追加していない(実質117種を新規収録)
- カードリストの誤りが見つかった場合は `js/cards.js` の `CARD_DB` を直接修正すればよい(データ駆動)

## 進化クリーチャー(第2弾で追加)
- バトルゾーンのクリーチャーは `{uid, tapped, sickness, stack:[{uid,cardId}, ...]}` という「スタック」
  で表現する。`stack` の最後尾(一番上)が現在の姿で、`engine.cardOf(inst)` が常にそれを返す
- 進化クリーチャーは手札から通常のコストを払って、進化元(`evolution.fromRaces` に一致する種族を
  持つ、自分のバトルゾーンのクリーチャー)の上に重ねる(`playEvolutionCard`)。**召喚酔いを受けない**
  ため出したターンにそのまま攻撃できる(公式のルール通り)
- バトルゾーンを離れる(破壊/バウンス/マナ送り/山札送り)時は進化元ごと束になって移動し、
  移動先ではバラバラの個別カードに戻る。各カードの「かわりに手札/マナに置く」等の置換効果は
  カードごとに個別に判定される
- 進化元の判定は「現在の一番上のカードの種族」で行うため、進化の上にさらに進化を重ねることも可能

## マナゾーン単色シナジー(第3弾で追加)
- 「自分のマナゾーンにあるカードがすべて○○文明である間」条件は `isManaMonoColor(side, civ)` で
  判定(マナが1枚もない場合は成立しない)。パワー上昇(`staticPowerIfManaMonoColor`)、ブロッカー付与
  (`blockerIfManaMonoColor`)、W・ブレイカー付与(`doubleBreakerIfManaMonoColor`)の3種類に対応
- 同文明カウントスケーリング(`powerPerOtherSameCivInBattle`)はバトルゾーンの「自分以外」の
  同文明クリーチャー数に比例してパワーが増える常時能力(混沌魚・牙男・奇面ざくろ等)
- 他クリーチャーへのオーラ付与系(`auraBuffOthersOfCivWhileAttacking`=攻撃中のみ固定値バフ、
  `auraGrantBlockerToOthersOfCiv`=ブロッカー付与、`auraGrantUnblockableToOthersOfCiv`=ブロック不可付与)
  は自分を含まず「他の同文明クリーチャー」にのみ及ぶ
- 破壊時の身代わり(`redirectAllyDeathTo`: 'hand' | 'mana')は、対象クリーチャーがバトルゾーンに
  いる間、他の同文明の味方が墓地に置かれる代わりに手札/マナに移動する置換効果(大昆虫ギガマンティス・
  絶望の魔黒ジャックバイパー)
- 破壊時にシールド化(`onDestroy: 'shield'`)は墓地の代わりに裏向きシールドとしてシールドゾーンへ
  (雷雲の守護者ラーザ・ベガ・予言者アレス)
- 進化クリーチャーの一番上のカードだけを墓地に送る「剥がし」効果(`peelTopOfEvolution`、シェル・
  ポーチ)は、スタックの最上段のみ墓地送りにし、破壊トリガーは発生させない(進化元は残る)
- 攻撃制限系: `cannotAttackIfOutnumbered`(バトルゾーンの数で相手に負けていると攻撃不可、奇襲兵
  ブルレイザー)、`cannotAttackCreatures`(クリーチャーを攻撃対象にできない、夜明けの超人)
- 呪文が墓地でなくマナゾーンに置かれる(`castGoesToMana`)は第2弾から存在するパターンをS・トリガー
  呪文(ライト・ブーメラン)にも適用
- シールドを好きな枚数選んでマナ化する効果(逆転のオーロラ)は `kind: 'shieldQuantity'` という
  疑似対象種別を使い、「0〜現在のシールド枚数」を選択肢として提示する(人間側はモーダルで数値を選択、
  CPU側は`ai.js`で2枚を上限とする簡易ヒューリスティックを使用)
- 魔流毒(「自分の闇のクリーチャーを1体破壊しなければ唱えられない」)は、唱える条件を「自分の闇の
  クリーチャーが1体以上いること」を対象存在チェックで表現し、破壊自体を対象選択の一部として実装
  (対象がいない場合はS・トリガーとしても使用不可)

## 両陣営に及ぶ部族オーラ・コスト税・ロック(第4弾で追加)
- 第4弾では「バトルゾーンにある○○(種族/文明)すべて」という記述のオーラ効果が多数登場し、原文の
  ままだと**両プレイヤーの該当クリーチャーに等しく作用する**(自分のものだけに限定する「自分の」が
  付いていない)。これらは `symmetricAura: { matchRace | matchCiv, powerBonus?, powerAttackerBonus?,
  grantsBlocker?, grantsDoubleBreaker? }` という単一のキーワードに統合し、`staticPowerBonus` /
  `powerWhileAttacking` / `isBlockerNow` / `isDoubleBreakerNow` の4箇所で両陣営のバトルゾーンを
  横断的に走査して判定する(邪妃グレゴリア・カオティック・ワイバーン・キング・アクアカムイ・
  チアフル・アビス・呪いの影シャドウ・ムーン・聖弓の求道者レ・ビール・ピッピ・クッピー・応援チューリップ)。
  実際のルーリングでは一部後年の再録でカード文面が「自分の」限定に変更されているが、本実装は
  紙のDM-04初出テキストに忠実な(相手のクリーチャーも強化してしまう)挙動を採用している
- 特定文明のカードを出す/唱えるコストを増やす「税」オーラは `taxCiv: {civ, amount}` として
  `effectiveCost` で両陣営を横断的に加算する(牢黒の伝道師ミリエス・偽りの影ヘル・スモーク・
  爆弾小僧ミサイルボーイ・カスミダケ)。テキストに「自分の」限定が無いため、同文明を採用していれば
  自分自身の同種カードにも課税される
- 特定文明以外の呪文をすべて封じる(`lockNonCivSpells`、聖霊王アルカディアス)は `playCard` の
  呪文分岐と `resolveShieldTrigger` のS・トリガー呪文分岐の両方でチェックする(唱えようとした
  カードは不発のまま墓地へ)
- 特定文明のS・トリガーを封じる(`lockShieldTriggerCiv`、暴風の求道者フ・レイル/ギガボルバ)は
  シールドブレイク時点(`breakShields`)で判定し、封じられていればそもそも `pendingShieldTriggers`
  に積まない(手札には通常通り加わるが、その場でのトリガー起動はできない)
- 「他のクリーチャーがバトルゾーンに出た時/破壊された時、ドローしてよい」という汎用ウォッチャー
  能力(`drawOnAnyCreatureEtb`=雷鳴の守護者ミスト・リエス、`drawOnAnyCreatureDestroyed`=屑男)は、
  召喚・進化・S・トリガー召喚のすべての「クリーチャーがバトルゾーンに出る」経路で呼ばれる
  `onCreatureEnteredBattle` フックと、`destroyCreature` 内の破壊後フックとして実装。両陣営どちら側の
  クリーチャーの出入りにも反応する(「他の」なので自分自身の出現には反応しない)
- 特定文明のみアンタップ状態でも攻撃できる(`canAttackUntappedOfCiv`、飛翔の精霊アリエス/荒廃の巨王
  ジェノサイド)は既存の`untapKiller`とは別キーワードとして実装し、対象文明以外へはタップ状態のクリー
  チャーしか攻撃対象にできない従来ルールのまま。両カードとも`cannotAttackPlayer`と併用し、プレイヤー
  への直接攻撃は一切できない専用の除去役として機能する
- 特定文明の攻撃・ブロックを回避する(`evadeCiv`、神速の守護者グラン・リエス/パープル・ピアス)は
  「その文明のクリーチャーからは攻撃対象にされず、かつその文明のクリーチャーにはブロックされない」
  の両方を意味し、`validCreatureAttackTargets`(攻撃側)と`eligibleBlockers`(ブロック側)の両方で判定
  する。単独で「ブロックされない」のみを持つ`cannotBeBlockedByCiv`(いにしえの超人)とは区別する
- 対象数が実行時の場の状況で変わる効果(彗星の精霊リムエル=自分の未タップ光マナの枚数分だけ相手
  クリーチャーをタップ、悪魔の契約=マナから好きな枚数を墓地に置いて同数ドロー、メガ・ブラスター=
  手札を捨てた枚数分の自分のクリーチャーにW・ブレイカー付与)に対応するため、対象仕様の`max`に
  数値だけでなく`(engine, side) => number`という関数も渡せるよう`main.js`の`promptTargetSelection`と
  `ai.js`の`chooseTargetsForCpu`を拡張した
- ハイドロ・ハリケーン(自分の光クリーチャー数につき相手マナをバウンス、自分の闇クリーチャー数
  につき相手クリーチャーをバウンス)は、本来は1回ごとに任意の対象を選べる「してもよい」の連続効果だが、
  1つの効果オブジェクトが持てる対象種別は1種類という設計上の制約から、常に最もコストの高いマナ/
  最もパワーの高いクリーチャーを自動選択してバウンスする形に簡略化した
- いけにえの鎖(相手クリーチャーを2体まで破壊し、自分のクリーチャーがいれば1体を道連れに破壊)は、
  相手への破壊は通常通り対象選択させ、自分自身の生け贄選択は簡略化のため`pickWeakestOwnCreatureUid`
  で最もパワーの低いクリーチャーを自動選択する(他の「相手/自分が選ぶ」効果の簡略化方針と統一)
- CIP能力のうち対象を取らない(`target: null`)ものが「場に出た自分自身」を除外して数える必要がある
  場合(凶骨の邪将クエイクス=自分の"他の"闇クリーチャー数を数える)のために、`_resolvingAttackerUid`
  と同様の一時参照として`_resolvingCipUid`を追加し、`playCard`/`playEvolutionCard`/
  `resolveShieldTrigger`のいずれの経路でCIPが即時解決される場合も解決中だけ設定される

## サバイバー・T(トリプル)・ブレイカー・スピードアタッカー(第5弾で追加)
- **サバイバー**: 第5弾で追加された種族。「サバイバーの長」カードは自分自身の能力を直接キーワードとして
  持つと同時に `survivorGrants: '<キーワード名>'` を持ち、「このクリーチャーがバトルゾーンにある間、
  自分の他のサバイバーも上の能力を得る」という共有オーラを表現する。真偽値系キーワード
  (`blocker`/`slayer`/`unblockable`/`doubleBreaker`)は`hasEffectiveKeyword(side,inst,key)`で、
  数値/オブジェクト系キーワード(`powerAttacker`/`staticPowerFlat`/`endOfTurnUntap`/`onDestroy`)は
  `effectiveKeywordValue(side,inst,key)`で判定する。いずれも「自身が種族にサバイバーを含み、かつ
  同じ側の他のバトルゾーンのクリーチャーに`survivorGrants`が一致するものがいる」場合に、その長自身の
  キーワード値を借りて適用する。攻撃時トリガー(ドロー・ハンデス等)の共有だけは`onAttack`という
  ability オブジェクトそのものを共有する必要があるため、専用の`triggerSurvivorOnAttack`で
  対象を取らない(`target: null`)ものに限り、攻撃するたびに他のサバイバーの長のability.resolveを
  追加で呼び出す形で実装している
- **T(トリプル)・ブレイカー**: シールドを3枚ブレイクする。`breakerCountNow(side,inst)`が
  `tripleBreaker`→3、W・ブレイカー相当→2、それ以外→1を返し、`resolveCombat`のプレイヤー攻撃時は
  常にこのメソッドの戻り値を使う(旧`isDoubleBreakerNow(...)?2:1`から置き換え)
- **スピードアタッカー**: 召喚酔いを受けない。`playCard`と`resolveShieldTrigger`のクリーチャー生成
  直後に、`speedAttacker`キーワードを持つ場合は即座に`sickness=false`を設定する(進化クリーチャーの
  「召喚酔いを受けない」処理と同じタイミング・考え方)
- **セイバー**(ポッポ・チャッピー): 「このクリーチャーがバトルゾーンにある間、自分の指定種族の
  クリーチャーが破壊される代わりにこのクリーチャーが破壊される」という身代わり効果。
  `saberProtectsRace`キーワードで表現し、`destroyCreature`の冒頭で、実際に破壊されるクリーチャーを
  決定する前に同じ側のセイバー持ちを探して破壊対象を差し替える。本来は「してもよい」の任意効果だが、
  常に身代わりを選択する(自分のクリーチャーを守れるなら守った方がほぼ常に得なため)簡略化とした
- **T・ブレイカー/W・ブレイカーで割られた時に相手シールドが1枚でもあれば追加ブレイク**
  (神拳の超人の「ブロックされた時」効果)は`breakShieldWhenBlocked`キーワードで表現し、
  `resolveCombat`のブロックされた分岐の最後で判定する
- **文明限定スレイヤー**(ギガゲイル・エターナル・クライ=自然/光限定)は`slayerVsCiv`キーワードと
  モジュール関数`civSlayerMatches`で表現し、`resolveCombat`のスレイヤー判定に汎用スレイヤーと
  併せてOR条件で組み込む
- **攻撃対象/被ブロックの文明制限**が第4弾よりさらに細分化された: `blockerVsCiv`(このブロッカーは
  指定文明の攻撃しかブロックできない、バウンサー・イール)、`cannotBeBlockedByPowerAtLeast`
  (一定パワー以上のクリーチャーにブロックされない、乱雲の使徒カルゴ)、`cannotBeAttackedByCiv`
  (指定文明からは攻撃対象にされない、スチールアーム・クラスター)、`canOnlyAttackUntappedOfCivs`
  (通常ルールを完全に置き換え、指定文明の未タップクリーチャーしか攻撃できない、ストームジャベリン・
  ワイバーン)、`cannotAttackIfEnemyShieldless`(相手シールドが0枚の間は攻撃できない、剣舞の修羅
  ヴァシュナ/ギガゾウル)
- **マナ回避**(神魂の守護者シュノーク・ラー): 「相手の効果で自分のマナが墓地に置かれる代わりに
  マナゾーンにとどめる」を`manaGraveyardProtection`キーワードで表現し、`manaCardToGraveyard`
  (相手側からの効果でのみ呼ばれる想定のメソッド)の冒頭でガードする。自分自身の効果でマナを墓地に
  送る場合(`sendOwnManaToGraveyard`等)は経由しないため、正しく「相手による」場合のみ保護される
- **S・トリガーを使われたらアンタップしてもよい**(ポコルル)は、`resolveCombat`でプレイヤーへの
  攻撃時に`_lastBreakAttackerUid`/`_lastBreakAttackerSide`を記録し、`resolveShieldTrigger`で
  トリガーが実際に使われた直後にそのクリーチャーが`untapOnTriggerUse`を持っていればアンタップする
- **このターンシールドをブレイクするたびにドロー**(ミラクル・サーチャー)と**ターン終了時に
  ブレイクした枚数だけ山札から手札に加える**(ビースト・チャージ)は、どちらも`breakShields`が
  受け取る`breakerSide`引数を使って`turnFlags[breakerSide].shieldsBrokenThisTurn`を毎回加算し、
  前者は同じタイミングで`turnFlags[side].drawOnBreak`を見て即座にドロー、後者は`endTurn`の冒頭
  (`turnFlags`をリセットする前)で`beastChargeActive`フラグを見て`autoTutorMultiFromDeck`を呼ぶ
  (本来は公開して複数枚を任意に選べる効果だが、複数選択UIが無いためコスト降順で自動選択する簡略化)
- **相手の次のターン、攻撃可能なクリーチャーをすべて強制攻撃させる**(ファントム・ベール)は、
  `turnFlags`と違って自ターン終了時にリセットされない`this.forceAllAttackSide`という専用フィールドを
  新設し、対象側が`runForcedAttackers`を呼んだ時(人間・CPUどちら側の攻撃フェーズ開始時にも
  `main.js`/`ai.js`から必ず呼ばれる)に一度だけ全クリーチャーを強制攻撃させてフラグを消費する
- **相手の手札を見て1枚選んで捨てさせる**(策略の手)のために、新しい対象種別`enemyHandCard`
  (相手の手札)を追加し、`main.js`のラベル表示・`ai.js`の対象選択ヒューリスティック(相手にとって
  最もコストの高いカードを捨てさせる)にも対応した
- **ハイドロ・ハリケーン系の「連続する任意選択」簡略化パターンを踏襲**した効果として、
  竜脈噴火(自分の自然クリーチャー数につき相手マナ破壊)・サンダー・ネット(自分の水クリーチャー数
  につき相手タップ)があり、対象仕様の`max`に動的関数を渡す第4弾の仕組みをそのまま再利用している

## タップ能力(TT)・マッドネス・山札破壊・シールド焼却(第6弾で追加)
- **タップ能力(TT)**: 「このクリーチャーで攻撃する代わりに、タップして次の能力を使ってもよい」という
  新しい行動選択肢。カード定義に`tapAbility: {target, resolve}`(onPlay/onAttackと同じ形式)を持たせ、
  攻撃フェーズ中に`useTapAbility(side, uid)`で攻撃の代わりに発動できる。攻撃可能条件(未タップ・
  召喚酔いでない)と同じ条件を`canUseTapAbility`で判定する。一部のカード(守護聖天アーク・バイン・
  フォート・メガクラスター・超空要塞バビロン・超幻獣グラザルド・甲冑神龍エグゼキューター)は
  自分自身のタップ能力を、`tapAbilityGrantToCiv: '<文明>'`によって同じ文明の自分の他のクリーチャー
  にも共有する(そのクリーチャー自身をタップして使う)。`resolveTapAbilityFor`が「自分の能力→
  他カードから借用できる能力」の順で解決する。UIは`main.js`の「タップ能力を使う」ボタン、
  CPUは`ai.js`で通常の攻撃ループの後、まだ使われていない・攻撃しなかったクリーチャーに対して
  機会的に使用する(攻撃を優先する簡易ヒューリスティックのため、実際の対人戦ほど頻繁には使わない)
- **マッドネス**: 「相手のターン中に、このカードが手札から自分の墓地に置かれる時、代わりにバトル
  ゾーンに出す」という置換効果(飛雲の求道者ダバ・トーレ)。手札を捨てる系の共通処理
  (`discardRandomFromHand`/`forceDiscardWorstN`/`handCardToGraveyard`/`discardAllHand`)をすべて
  `sendHandCardToGraveyardOrMadness(side, cardObj)`経由に統一し、そこで`this.turnSide !== side`
  (=捨てる側の自分のターンではない)かつ`madness`キーワード持ちなら墓地の代わりにバトルゾーンへ出す
  ように一元化した。CIPに対象選択が必要な場合は候補の先頭から自動選択する(既存のサバイバー共有CIP
  の簡略化方針と統一)
- **山札破壊**: 相手の山札を(内容を伏せずに)見て、選んだカードを墓地に置く効果(ヘル・スラッシュ)。
  新しい対象種別`enemyDeckCard`(相手の山札)を追加し、`millChosenFromDeck`で選んだカードを墓地へ
  移してからシャッフルする。CPU側は`ai.js`でコストの高いカードを優先して選ぶ
- **シールド焼却**: シールドをブレイクしても手札に加わらず、S・トリガーも使えないまま持ち主の墓地に
  置かれる効果。攻撃でブレイクする場合は`shieldBurnOnBreak`キーワード(ボルメテウス・ホワイト・
  ドラゴン)を`resolveCombat`が検知し、`breakShields`に`burnMode`フラグを渡して墓地送りに切り替える。
  呪文で相手のシールドを直接焼却する場合(インビンシブル・フォートレス)は`burnOpponentShields`で
  裏向きのまま(内容を公開せず)墓地に送る — シールドは本来非公開情報のため、「選ぶ」動作も内容を
  見ずに行われる
- **T(トリプル)・ブレイカーの一時付与**: 第5弾の`tripleBreaker`キーワードは常時付与のみだったため、
  インビンシブル・パワーのような「このターンだけT・ブレイカーを得る」を表現するために
  `tempTripleBreaker`という一時フラグと`teamGrantTripleBreaker(side)`を追加した
  (`tempDoubleBreaker`/`teamGrantDoubleBreaker`と対になる設計)
- **一時的なスレイヤー付与**も同様の理由で`tempSlayerGrant`を追加(刃滅人形ポールのタップ能力)。
  種族全体への常時スレイヤー付与(恐慌の魔黒デス・スペクター、自分自身を含む)は別に
  `auraGrantSlayerToOwnRace`という専用キーワードと`hasRaceGrantedSlayer`で判定する(サバイバーの
  「他の」と違い、種族が一致する自分自身も対象に含まれるため、既存の`hasEffectiveKeyword`とは
  別ロジックとした)
- **ブロックされてもバトルが発生しない**攻撃側(ピーカプ・リザード等)・ブロック側
  (不屈の使徒チーキ・クーレ)は、それぞれ`noBattleWhenBlocked`/`noBattleWhenBlocking`キーワードで
  表現し、`resolveCombat`のブロック分岐でバトル自体をスキップする(両者はタップされたまま、勝敗
  判定も破壊も一切発生しない)
- **相手の召喚/呪文詠唱に反応して一時的にブロッカーを得る**(キング・トラファルガー等)は
  `blockerOnOpponentAction`キーワードと`triggerBlockerOnOpponentAction`で、`playCard`のクリーチャー
  召喚・呪文詠唱の両方、および`resolveShieldTrigger`のS・トリガー経路すべてから呼び出す。既存の
  `tempBlockerGrant`(ターン終了時にクリアされる)をそのまま利用する
- **呪文を唱えたターンのみ召喚できる**(綺羅星の精霊ガリアル等)は`requiresSpellCastThisTurn`
  キーワードと`turnFlags[side].spellCastThisTurn`(呪文を唱えた/S・トリガーで唱えた時に立てる)で
  判定し、`playCard`の召喚ガードで参照する
- **自分の他のクリーチャーを1体生け贄にしなければ攻撃できない**(憤怒の猛将ダイダロス)は
  `mustSacrificeToAttack`キーワードで、`canAttackAtAll`(生け贄がいなければ攻撃自体が不可)と
  `declareAttack`(生け贄を自動選択して破壊してから攻撃を続行)の両方で判定する
- **「求心」的な種族強制ターゲット**(戦いの化身=ミステリー・トーテムを優先的に攻撃させる)は
  `forcesAttacksAgainstRace`キーワードと`getForcedAttackTargets`で表現し、`declareAttack`と
  `validCreatureAttackTargets`の両方で、対象となる種族が場にいる間はプレイヤーへの攻撃も対象外の
  クリーチャーへの攻撃も禁止する
- **進化クリーチャーがタップされた状態でバトルゾーンに出る**(銀界の守護者ル・ギラ・レシール、
  文面に「自分の」が無いため両陣営に等しく作用する第4/5弾の対称オーラの方針を踏襲)は
  `evolutionEntersTapped`キーワードで、`playEvolutionCard`が進化の直後にチェックする
- **どんな種族の進化クリーチャーでも上に置ける汎用進化元**(無垢の宝剣)は`universalEvolutionBase`
  キーワードで、`getEvolutionTargets`が種族チェックより先に判定する
- **特定種族のみ召喚コストを下げる**(コッコ・ルピア=ドラゴン)は、第2弾からある`costReduction`
  (カード種別ベース)とは別に`costReductionRace`(種族ベース)を追加し、`effectiveCost`で両方を
  加算的に処理する
- **自分の場に指定文明の他のクリーチャーがいる/いないかで攻撃中のみパワーが変わる**(捜神兵
  グチェラリオン=不在時、炎獣兵マグナム・ブルース=在時)は`powerAttackerIfOwnCivCondition`
  ({civ, amount, requireAbsent})という単一のキーワードで両方向に対応する。グチェラリオンはさらに
  不在時にW・ブレイカーも得るため`doubleBreakerIfOwnCivAbsent`も別途判定する
- **自分の他のクリーチャーにアンタップ状態のものが1体でもあれば攻撃できない**(神秘の超人、通常の
  「タップ済みでなければ攻撃できない」ケースとは逆方向の条件)は`cannotAttackIfOtherUntapped`で
  `canAttackAtAll`に追加した
- **相手クリーチャーを最大N体まで攻撃対象として選び、ブロッカー以外のクリーチャーだけを攻撃できる**
  (戦男)は`canOnlyAttackBlockers`で`validCreatureAttackTargets`に追加した

## アーキテクチャ
- `js/state.js` — `nextUid`、デッキ(`duelmasters.decks.v1`)と戦績(`duelmasters.meta.v1`)の localStorage 永続化
- `js/cards.js` — カードDB(477種)、文明定義、キーワード能力ヘルパー、効果ファクトリ関数群、デッキ検証
- `js/engine.js` — `DuelEngine` クラス。ターン進行、マナ支払い(コスト軽減オーラ・両陣営コスト税を
  考慮した`effectiveCost`)、進化(`playEvolutionCard`/`getEvolutionTargets`)、攻撃対象制限
  (特定文明限定のアンタップキラー・回避・専用置き換えを含む)、ブロック可否判定(パワー条件付き/
  種族グローバル不可/マナ単色条件/特定文明ブロック不可・回避・被ブロック制限を含む)、攻撃時能力
  (`onAttack`、`pendingAttackTrigger`でブロック判定より先に解決。`_resolvingAttackerUid` で
  自己参照可能。`triggerSurvivorOnAttack`でサバイバーの長からの共有攻撃時能力も発火)、CIP能力の
  即時解決時の自己参照(`_resolvingCipUid`)、バトル解決(スレイヤー・文明限定スレイヤー・バトル後
  自壊・ブロック後アンタップ・ブロックされた時の追加ブレイク等)、シールドブレイクとS・トリガーの
  キュー管理(文明別ロック・ブレイク枚数記録・トリガー使用時アンタップを考慮)、呪文詠唱ロック、
  マナ単色シナジー(`isManaMonoColor`)、両陣営を横断する部族/文明オーラ(`symmetricAura`)、
  サバイバーの共有オーラ(`hasEffectiveKeyword`/`effectiveKeywordValue`)、セイバーの身代わり
  破壊、マナ守護、クリーチャーの出入りに反応する汎用ウォッチャー(`onCreatureEnteredBattle`)
- `js/ai.js` — CPUの意思決定(マナチャージ・プレイ・進化・攻撃・攻撃時能力・ブロック・S・トリガー・
  `ownManaCard`/`shieldQuantity`/`enemyHandCard`/`enemyDeckCard`を含む対象選択ヒューリスティック、
  実行時に変わる対象数の解決、通常の攻撃ループの後にタップ能力を機会的に使用)
- `js/decks.js` — CPU用プリセットデッキ(各文明の全カード=DM-01〜06をレアリティ別
  採用枚数で40枚以上に構築、モノカラー5種。進化とその進化元が自然と同じデッキに入るよう文明単位で構築)
- `js/main.js` — 画面遷移・DOM描画・対象選択モーダル(実行時に変わる対象数を含む)・進化元選択・
  攻撃時能力の対象選択・タップ能力の使用と対象選択(`btnUseTapAbility`)

## ルール実装上の設計判断・簡略化
- シールドは自分の分も含めて内容を伏せて表示。ブレイクされて初めて中身が分かる
- クリーチャーを攻撃対象にできるのは原則タップ状態のもののみ。アンタップキラー/一時許可/
  「タップされていなくても攻撃できる」チーム効果(クエイク・ゲート等)は例外
- パワーアタッカー系(固定値/条件付き/他の数につき増加/墓地枚数につき増加)は「攻撃中のみ」、
  種族オーラ(機神装甲ヴァルディオス等)は「常時」など、キーワードごとに適用タイミングを区別
- スレイヤーは「相手を戦闘結果に関わらず破壊」、バトル後自壊は「結果に関わらず自分も破壊」
- 「相手が自分のクリーチャーを選ぶ」効果(腐食虫スワンプワーム等)は簡略化のため、常に相手側の
  一番パワーが低いクリーチャーを自動選択する(効果自体は正確、選ぶ主体だけ簡略化)
- 手札を見ずに選ぶハンデスは完全ランダムで自動解決。相手のシールドを見る効果は状態を変えず、
  人間プレイヤー側が見た時だけログに内容を表示する(CPU側が見た内容は人間には見せない)
- 山札を見て1枚加える/マナに置く系は、実際の山札全体から検索するモーダルを実装
- ダイヤモンド・カッターの「攻撃制限を全て無視」は召喚酔い・攻撃不可・相手プレイヤー攻撃不可を
  まとめてターン中バイパスするフラグ(`turnFlags[side].ignoreAttackRestrictions`)として実装
- マナ支払いの文明チェックは「デュエルマスタープレイス」仕様: 必要な文明のカードがマナゾーンに
  1枚でも存在すれば(タップ済みでも可)コストは支払え、実際にタップする札は文明を問わず先頭から
  必要枚数を機械的にタップするだけでよい(紙のTCGの「タップする札の中に文明を含める」制約より緩い)
- 自分/相手のマナゾーンには文明ごとの内訳(未タップ/合計)を色付きタグで常時表示する
  (マナゾーンは公開領域のため、相手の内訳も見せて問題ない)
- 灼熱波・スネークアタックの「自分のシールドが1枚でもあれば裏向きのまま1枚選び墓地に置く」は
  コストではなく付随効果として簡略化し、`millOwnShieldRandom` でランダムな1枚を内容を見ずに墓地送り

## 未実装/今後の拡張候補
- クラウド同期、ローカル2人対戦は今回スコープ外
- CPU用プリセットは現状モノカラー5種のみ。多色デッキや難易度差のあるCPUの追加は容易(`js/decks.js`)。
  加えてCPU対戦相手選択画面では、プレイヤーが保存した(条件を満たす)デッキも「あなたが編成したデッキ」
  として選択でき、CPUがそのままそのデッキを使って対戦する(ミラーマッチや自作デッキの練習用)
- 「相手が自分のクリーチャーを選ぶ」効果を実際に相手側(人間プレイヤーの番)で選ばせるインタラクティブ化
- ハイドロ・ハリケーンのような「連続する任意選択の対象選択」を、自動選択ではなく実際にプレイヤーが
  1件ずつ選べるようにするには、1つの効果が複数種類の対象仕様を順に持てる仕組みへの拡張が必要
- ビースト・チャージのような「山札を公開して複数枚を任意に選ぶ」効果も同様に、複数選択UIが無いため
  自動選択(コスト降順)に簡略化している。プレイヤーが実際に選べるようにするには複数選択モーダルが必要
- 第7弾以降を追加する場合も同じデータ駆動構造(`CARD_DB`への追加+必要なら新キーワード実装)で対応可能
